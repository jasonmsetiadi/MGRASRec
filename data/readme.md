# Data Pipeline

## Input file structure

| Input | MicroLens | Amazon |
|---|---|---|
| Train pairs | `data/microlens/Split/train_pairs.csv` | `data/amazon/Split/{DATASET}/train_pairs.csv` |
| Val pairs | `data/microlens/Split/val_pairs.csv` | `data/amazon/Split/{DATASET}/val_pairs.csv` |
| Test pairs | `data/microlens/Split/test_pairs.csv` | `data/amazon/Split/{DATASET}/test_pairs.csv` |
| User history | `data/microlens/processed/user_items_negs.tsv` | `data/amazon/processed/{DATASET}_user_items_negs.tsv` |
| Item metadata | `data/microlens/processed/MicroLens-50k_titles.csv` | `data/amazon/processed/{DATASET}_item_desc.tsv` |
| Images folder | `data/microlens/MicroLens-50k_covers/` | `data/amazon/Amazon_images/{DATASET}/` |

Amazon paths include a `{DATASET}` subdirectory (`Baby_Products` or `Video_Games`) at every level, and user history is dataset-specific rather than shared.

## Preprocessing

The processed files are generated by `data/microlens/preprocessing.ipynb` for MicroLens and `data/amazon/process_data.py` for Amazon. Both follow the same pipeline steps below, with dataset-specific parameters noted where they differ.

### K-core filtering

Interactions are filtered iteratively until every remaining user has at least `min_u` interactions and every remaining item has at least `min_i` interactions. Users and items that fall below the threshold are removed together, and the process repeats until no more removals occur.

| Dataset | min\_u | min\_i |
|---|---|---|
| MicroLens | 7 | 5 |
| Amazon | 6 | 5 |

After filtering, Amazon additionally reindexes users and items to contiguous 0-based integer IDs and saves the mappings to `{DATASET}_u_map.tsv` and `{DATASET}_i_map.tsv`.

### Positive item selection

Only the top-k most frequent items per user are used as positives, sorted by timestamp, and saved to `user_items_negs.tsv`. This avoids passing the full interaction history to the LLM. The value of k is chosen to match the average sequence length after k-core filtering for each dataset.

| Dataset | Top-k positives |
|---|---|
| MicroLens | 6 |
| Amazon | 11 |

Items are ranked by global interaction frequency (most popular first); ties in Amazon are broken by timestamp. The selected items are then re-sorted chronologically before being written out.

### Negative sampling

For each user, up to 20 negative items are sampled — items the user has not interacted with.

| Dataset | Method | Random seed |
|---|---|---|
| MicroLens | `np.random.choice` without replacement from uninteracted items | 42 |
| Amazon | `rng.choice` with replacement from all items, then subtract the user's positive set; re-samples if fewer than the required count remain | 202404040331 |

### Train / val / test split

Users are split 80 / 10 / 10 by user ID using `train_test_split` with a fixed random seed. The split files are saved alongside `user_items_negs.tsv`.

| Dataset | Random seed |
|---|---|
| MicroLens | 42 |
| Amazon | 2024040331 |

## Item metadata

MicroLens item titles are pre-provided in `MicroLens-50k_titles.csv` and not generated by the preprocessing notebook. For Amazon, `process_data.py` also extracts item metadata from the raw `meta_{DATASET}.jsonl.gz` files, saving `item_id`, image URL (largest available), and a combined title + description string to `{DATASET}_item_desc.tsv`.
